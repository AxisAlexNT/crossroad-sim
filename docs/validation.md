# Проверка модели

Модель помогает сравнивать сценарии при явно заданных допущениях. Соответствие реальному движению требует измерений и отдельной проверки: успешные программные тесты сами по себе не подтверждают точность прогноза.

## Что проверяется

- Правила очерёдности, торможение, слияние потоков, перестроение и габариты транспорта.
- Воспроизводимость по исходным условиям, совместимость сохранений и устойчивость при разных шагах времени.
- Учёт ожидания, незавершённых поездок, внешней очереди и потери спроса.
- Фоновые расчёты, отмена, сохранение состояния и автономная работа страницы.

## Известные ограничения

Исправления взаимных блокировок проверяются на сохранённых состояниях и длительных расчётах с начала модели. Прохождение этих сценариев не гарантирует устойчивость произвольной схемы. Проверка нескольких шагов времени пока не подтверждает заданную точность средних ожиданий и задержек для всех схем; численную сходимость нельзя считать установленной.

Прогоны со столкновениями, потерей спроса, ошибками или вмешательством модели нельзя использовать как подтверждение улучшения программы светофоров. Для анализа нужны строгие расчёты, несколько заранее выбранных наборов случайных условий и доверительные интервалы. В наглядном режиме помощь при блокировке и освобождение места аварии отмечаются на карте, в журнале и счётчиках. Подбор фаз и сравнение экспериментов всегда выполняются в строгом режиме без автоматической эвакуации.

[Сохранённая модель](../validation/repro-interlocking-v106.session.json) и [снимок состояния](../validation/repro-interlocking-v106.replay.json) позволяют изучить известный случай. Снимок предназначен для диагностического скрипта; обычный импорт модели запускает расчёт сначала.

## Воспроизводимые команды

```sh
npm test
npm run build:check
npm run check:dist
npm run repro:interlocking
npm run repro:interlocking -- --from-start
STRICT=1 npm run test:stall -- 7200 10 '' 42 stall.json
npm run test:convergence -- 1200 30 '' convergence.json
```

Команда воспроизведения диагностирует известный дефект; её успешное выполнение не означает отсутствия ошибок модели. Для каждой матрицы необходимо сохранять версию движка, исходные условия, горизонт, шаг времени и все неудачные результаты. Изменение допусков или исключение неудобных прогонов после просмотра результатов недопустимо.

## Пересмотр нижней границы скорости поездок

17.11.2026 нижняя граница 3 км/ч в проверке статистики завершённых поездок заменена требованием конечной положительной скорости. Верхняя граница 70 км/ч сохранена. В сценарии `v1` с исходным числом 42 за 1800 с средние скорости составляют 2,12 км/ч для `E>S`, 1,95 км/ч для `W>N` и 2,64 км/ч для маршрута `325n`. Повторение на движке до добавления статистики подтвердило эти значения: ожидание внутри модели может снизить среднюю скорость ниже прежней границы.

Это явное изменение критерия после изучения результатов. Оно не подтверждает приемлемость задержек или точность модели. Проверка независимо сопоставляет завершения, время, путь и стоянки с наблюдаемым движением. Исходные условия, горизонт, правила движения и верхняя граница не изменены; низкие значения не округляются до порога и не исключаются из статистики.

Нижнюю границу следует пересмотреть при отдельном исследовании времени поездок и ожидания. Для такого пересмотра нужно заранее определить проверяемую величину и критерий, затем повторить тот же сценарий и матрицу строгих прогонов. Команда проверки:

```sh
node --import tsx scripts/trip-stats.ts
```

## Длительные ожидания при расширенной проверке

17.11.2026 отдельно рассмотрены два результата предустановки `worked`. Это узкие исключения при приёмке, а не изменение правил движения или утверждение об отсутствии задержек.

В проверке за 7200 с на пяти зёрнах 42, 1042, 2042, 3042 и 4042 получена 61 остановка категории `other` при исходном пределе 20. Все 61 остановка завершилась самостоятельно, 38 были прямым ожиданием пешеходов. Проверка охватывает десять часов модели, тогда как исходный предел проверялся на трёх часах. Предел не пересчитан, исходный неуспешный результат сохранён.

На зёрнах 4042 и 5042 строгая проверка сообщает о 14 случаях неподвижности не менее 300 с. Головные машины ждут свободного места за перекрёстком: в два последовательных разрешающих интервала выезд занят очередью за рейсовым автобусом на остановке, между ними действует красный сигнал. На зерне 5042 головная машина выезжает при t=5259 с. На зерне 4042 отдельное продолжение после контрольного горизонта 7200 с подтверждает выезд при t=7285 с. Столкновений, взаимных блокировок и вмешательств в этих продолжениях нет.

Только эти проверенные ожидания приняты как документированные исключения. Исходные проверки и их пределы 20 и 300 с остаются без изменений, поэтому команды сохраняют сообщения об этих случаях и не должны описываться как полностью пройденные. Все зёрна сохранены. Остальные находки требуют отдельной диагностики и исправления; требования к столкновениям, взаимным блокировкам и вмешательствам не ослаблены.

При повторном рассмотрении нужно отдельно оценить работу светофорной программы и автобусных остановок, а для счётчика остановок заранее выбрать единицу наблюдения. Действующие исключения не подтверждают приемлемость времени ожидания. Воспроизводимые команды:

```sh
STRICT=1 npm run test:stall -- 7200 10 '' 42 stall.json
npm run test:dwell -- 7200 5
```

## Сравнение суммарной задержки

17.11.2026 изменён критерий сравнения предустановок. Среднее ожидание завершивших ожидание машин зависит от состава проехавшего потока. Более полное обслуживание медленного направления может увеличить это среднее при уменьшении общей задержки. Число длительных остановок внутри перекрёстка также зависит от числа обслуженных поворотов.

Основной показатель сравнения — `delayArea`, суммарная потеря времени всех машин на подходах, соединительных траекториях и выездах, включая ожидание в очередях за пределами модели. Используется существующий расчёт потери времени относительно свободного движения. В показатель входят разгон, замедление на поворотах и стоянки автобусов.

Стандартная проверка охватывает 12 строк, 3600 с и зёрна 42, 1042, 2042. Суммарная потеря времени должна быть не выше 110 процентов исторического значения, число завершений — не ниже 97 процентов. Число пропущенных поворотов не должно превышать результат версии 1.1.0 при тех же условиях. Историческая основа — версия 1.0.7, а для проработанной модели — состояние после исправления удержания зон стоящими на красный машинами.

Предел опасных моментов сохранён: максимум исторического значения и значения версии 1.1.0, увеличенный на 15 процентов. Требования к столкновениям, наездам, взаимным блокировкам, вмешательствам и сохранению спроса действуют отдельно. Пределы проработанной модели по среднему ожиданию и остановкам категории `other` также сохранены.

Исходные отношения среднего ожидания и числа остановок и прежние находки выводятся в `originalBaselineFindings` как справочные. Действующие причины неуспеха перечислены в `baselineFindings`. Для пересмотра критерия сохраняются исходные величины, горизонты и все зёрна в `validation/dwell-baseline.json`. Изменение показателей сравнения не является подтверждением численной сходимости.

## Проверка на реальных данных

Нужны измеренные потоки по направлениям, очереди, интервалы прибытия, времена проезда и обслуживания остановок, пешеходные потоки и фактическая программа светофоров. Данные для настройки и независимой проверки разделяются заранее. До такой проверки результаты являются оценками в рамках модели и не служат единственным основанием для изменения организации движения.


## Предварительная сборка 1.1.1-preview.1

Ограничение выезда считает пополнение отдельно для каждой полосы по прошедшему времени. Встроенный узел и код из параметров проверяются на одинаковой последовательности вызовов в ограниченной песочнице.

Полная проверка выпуска не завершена. Для v5 суммарная задержка превышает исходную на 10,97% при контрольном пределе 10%. Быстрая публикация предварительной сборки не заменяет общий набор проверок. Ограничения и неудачные результаты сохранены для следующей проверки.

Для версии 1.1.1-preview.1 временно принят только остаточный рост задержки v5 до 549101,292927634 с в сумме по контрольным трём зёрнам. Это соответствует примерно 10,97% к исходному уровню. Исходное превышение предела 10% остаётся в выводе. Исключение не переносится на другую версию или канал и не изменяет ограничения столкновений, вмешательств, опасных моментов, проездов и пропущенных поворотов. Перед завершённым выпуском решение нужно пересмотреть.
