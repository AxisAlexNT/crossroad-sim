# Проверка модели

Модель помогает сравнивать сценарии при явно заданных допущениях. Соответствие реальному движению требует измерений и отдельной проверки: успешные программные тесты сами по себе не подтверждают точность прогноза.

## Что проверяется

- Правила очерёдности, торможение, слияние потоков, перестроение и габариты транспорта.
- Воспроизводимость по исходным условиям, совместимость сохранений и устойчивость при разных шагах времени.
- Учёт ожидания, незавершённых поездок, внешней очереди и потери спроса.
- Фоновые расчёты, отмена, сохранение состояния и автономная работа страницы.

## Известные ограничения

Исправления взаимных блокировок проверяются на сохранённых состояниях и длительных расчётах с начала модели. Прохождение этих сценариев не гарантирует устойчивость произвольной схемы. Проверка нескольких шагов времени пока не подтверждает заданную точность средних ожиданий и задержек для всех схем; численную сходимость нельзя считать установленной.

Прогоны со столкновениями, потерей спроса, ошибками или вмешательством модели нельзя использовать как подтверждение улучшения программы светофоров. Для анализа нужны строгие расчёты, несколько заранее выбранных наборов случайных условий и доверительные интервалы. В наглядном режиме помощь при блокировке и освобождение места аварии отмечаются на карте, в журнале и счётчиках. Подбор фаз и сравнение экспериментов всегда выполняются в строгом режиме без автоматической эвакуации.

[Сохранённая модель](../validation/repro-interlocking-v106.session.json) и [снимок состояния](../validation/repro-interlocking-v106.replay.json) позволяют изучить известный случай. Снимок предназначен для диагностического скрипта; обычный импорт модели запускает расчёт сначала.

## Воспроизводимые команды

```sh
npm test
npm run build:check
npm run check:dist
npm run repro:interlocking
npm run repro:interlocking -- --from-start
STRICT=1 npm run test:stall -- 7200 10 '' 42 stall.json
npm run test:convergence -- 1200 30 '' convergence.json
```

Команда воспроизведения диагностирует известный дефект; её успешное выполнение не означает отсутствия ошибок модели. Для каждой матрицы необходимо сохранять версию движка, исходные условия, горизонт, шаг времени и все неудачные результаты. Изменение допусков или исключение неудобных прогонов после просмотра результатов недопустимо.

## Проверка на реальных данных

Нужны измеренные потоки по направлениям, очереди, интервалы прибытия, времена проезда и обслуживания остановок, пешеходные потоки и фактическая программа светофоров. Данные для настройки и независимой проверки разделяются заранее. До такой проверки результаты являются оценками в рамках модели и не служат единственным основанием для изменения организации движения.
