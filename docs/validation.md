# Проверка модели

Вычислительная проверка и соответствие натурным наблюдениям — отдельные этапы. Успешные тесты не доказывают точность прогноза реального движения.

## Текущий статус

**v1.0.6 — промежуточный выпуск, движок 2.1-dev.65.** Выпуск сохраняет текущий результат разработки и не объявляет модель прошедшей общую вычислительную приёмку. Полный `npm test` прошёл, включая 22 публичных регрессионных случая и проверку типов. Итоговые `build:check` и `check:dist` прошли: HTML 3,93 МиБ при лимите 5 МиБ, основной скрипт и три Worker соответствуют ES2019. В изолированном настольном Firefox проверены запуск разработки, автономный файл, движение, версия v1.0.6 и прокручиваемая история изменений; автономный файл не загружал HTTP(S)-ресурсы. Хеш проверенного HTML: `84bf6f61f05dbed314cdb3d76a817052bce2820ef9b67a1063b6b4b625a2d152`. Оба способа повтора опубликованного примера воспроизвели блокировку с совпадающим хешем движка. Строгая и численная матрицы этой ревизии целиком не выполнены. В длительном повторе сохраняется взаимная блокировка на секунде 10265.

Проверка свободного места за зоной больше не отменяется после длительного ожидания. Принятая уступка учитывается до освобождения зоны задним краем, в том числе после перехода на выезд. Ещё не начатое право проезда может быть согласованно возвращено через замкнутую неподвижную цепочку: путь нового получателя должен быть свободен, прежнее владение снимается вместе с передачей нового. Среди способных завершить проезд выбирается раньше въехавший участник. Ожидание своего лидера также учитывается в такой цепочке. Все эти правила являются допущениями модели и требуют проверки.

Известный дефект сохранён в [импортируемой сессии](../validation/repro-interlocking-v106.session.json) и [снимке состояния](../validation/repro-interlocking-v106.replay.json). Команда `npm run repro:interlocking` продолжает снимок, `npm run repro:interlocking -- --from-start` повторяет расчёт от нуля. Пример не скрывает дефект и не считается успешной проверкой отсутствия блокировок.

Ниже приведены результаты прежних ревизий. Их успешные проверки не заменяют приёмку текущих правил.

Подготовка интерфейса к версии приложения `1.0.6` не означает завершения приёмки движка или готовности к публикации. Вкладка «О модели» показывает тот же `CHANGELOG.MD`, который находится в репозитории, как прокручиваемый текст без сетевой загрузки. Номер интерфейса берётся из версии пакета. Кандидат сохраняет торможение перед точкой ожидания, когда оставшегося пути достаточно для остановки. Прежний дополнительный запас 0,3 м мог отменить уже действующую уступку в последних сантиметрах. Экстренная проверка подходящего потока учитывает расстояние до конфликта. Момент принятия резерва учитывает и отступ от зоны, и дистанцию покоя. Ожидание поворачивающего лидера на общей части полосы и ожидание слияния распознаются как очередь при подтверждённом перекрытии пути кузовом до конфликтной зоны. Адресное согласие очереди на своём подходе может учитываться через неподвижную цепочку другого потока, если весь путь свободен от кузовов участников цепочки. Новые локальные тесты воспроизвели отказы до исправлений; полная регрессия и матрицы текущего кандидата ещё не завершены.

Ревизия **2.1-dev.51** отделяет идентичность входного события от номера размещённой машины, восстанавливает точные времена прибытия и учитывает только доступную часть первого шага. Равномерные источники и пачки обрабатывают несколько событий за шаг, ступенчатый профиль интегрируется по частям. Встроенные источники и сгенерированный код сохраняют одинаковую числовую точность. Ревизия **2.1-dev.50** устраняет взаимное торможение с уже замедляющейся машиной, адресно уступающей приоритетному участнику и останавливающейся до зоны. Проверка возобновления движения теперь учитывает конкретные кузова также при проверке встречного резерва. Коридор для длинного автобуса не удерживает пару коротких машин, чьи траектории кузовов не пересекаются. Цепочка неподвижного ожидания до адресной уступки больше не ограничивается тремя участниками. Повторный номер прекращает обход, движущийся участник отменяет такую передачу, а весь путь получателя должен оставаться свободным от кузовов всех участников цепочки. В движке также сохраняется принятая адресная уступка: её резерв учитывается до завершения проезда, входит в снимки и очищается при отзыве резерва или смене траектории. Принять уступку может машина со свободным путём без неподвижного лидера на своём направлении, включая другие варианты той же пары полос.

Браузерные отчёты содержат хеш проверенного HTML или исходников. Проверка старой ревизии доказывает только зафиксированный сценарий этой ревизии; она не является полной приёмкой последующих изменений. Эмуляция размера экрана не заменяет физический смартфон.

## Команды проверки

```sh
npm test
npm run build:check
npm run check:dist
STRICT=1 npm run test:stall -- 7200 10 '' 42 stall.json
npm run test:convergence -- 1200 30 '' convergence.json
# Дополнительное исследование более мелких шагов, исходный отказ сохраняется
npm run test:convergence -- 1200 30 template-cross4 finer.json .1,.05,.02
node --import tsx scripts/snapshot-profile.ts snapshot-profile.json
```

Строгая матрица проверяет все шесть предустановок и три дополнительных шаблона. Неподвижность более 300 с, устойчивые взаимные блокировки и любые события непригодности отклоняют проверку. Диагностический разъезд не используется для прохождения приёмки. Проверяется весь прогон, включая прогрев. Признаки перегрузки сохраняются как отказы, а не скрываются удалением неудачных повторов.

Структурированный отчёт матрицы сохраняется после каждого повтора: версия и хеш движка, хеш скрипта, зёрна, фактическое время, счётчики и все находки. `completed: false` означает, что всей матрицы ещё нет. Исключение записывается как отказ; остальные повторы продолжаются. Горизонт, не кратный 10 с, также выполняется до указанного времени. CI запускает регрессию на изменениях; длительные проверки — вручную и по расписанию, с сохранением отчётов даже при отказе. Выполнение изменённого CI на удалённом сервере ещё не проверялось.

Цепочку ожидания можно воспроизвести отдельно, не меняя критерии пригодности:

```sh
node --import tsx scripts/trace-wait.ts v2 5042 925 2500 3100 wait-trace.json
```

Аргументы: модель, зерно, id машины, начало и конец наблюдения в секундах, выходной JSON. Сохраняются снимки каждые 10 с, цепочка причин, обслуживаемые автобусы и хеши движка и скрипта. Это выборка состояний, а не полный журнал событий; исчезновение машины само по себе не доказывает успешный выезд.

## Численная чувствительность

Одни и те же зёрна выполняются с шагами 0,2 / 0,1 / 0,05 с, прогревом 300 с и окном 1200 с. Записываются все результаты, входной спрос, причины непригодности, версия и хеш движка. Непригодный повтор или несовпадение входного спроса отклоняет проверку модели. Начиная с ревизии 51 сверяется также SHA-256 последовательностей событий по источникам: время, порядковый номер, атрибуты и зерно водителя. Аудит работает поточно в проверочном скрипте, не хранит полную историю и не включён в обычное воспроизведение. Максимум очереди сбрасывается после прогрева, как в экспериментах и подборе фаз.

Для соседних шагов вычисляются средняя парная разность и 95-процентный интервал Стьюдента по зёрнам. При числе степеней свободы более 30 используется консервативная граница для 30. Интервал оценивает неопределённость при своих статистических предположениях; он не доказывает порядок сходимости или натурную точность.

Инженерный допуск — максимум из 5 % среднего на самом мелком шаге и абсолютной границы: 5 авт/ч для выпуска, 1 с для ожидания и потери времени, 1 автомобиль для максимальной очереди. Весь интервал должен находиться внутри допуска на обоих переходах. Границы не расширяются по результатам расчёта. Расширение выборки с 10 до 30 зёрен является исследовательским уточнением, а не независимым подтверждением после выбора объёма по результату. Первоначальные отказы сохраняются.

Дополнительная диагностика на `skew / 1042` сопоставила все 377 появившихся машин по исходным атрибутам. При шагах 0,2 и 0,05 с восемь машин получили разные числовые номера, при шагах 0,1 и 0,05 с — две. Номера назначаются при размещении на дороге и зависят от группировки прибытий по шагам. Поскольку номер используется в разрешении равного приоритета, совпадение количества прибытий само по себе не доказывает идентичность всех входных условий. Влияние этого механизма на оставшиеся отказы численной чувствительности ещё не установлено.

Для независимой проверки замороженной ревизии 51 заранее зафиксирован отдельный протокол: все девять моделей, 100 зёрен от 50042 до 149042 с шагом 1000, прогрев 300 с, окно 1200 с, шаги 0,2 / 0,1 / 0,05 с и прежние допуски. Это 2700 прогонов на зёрнах, не использованных в исследовательской серии. Все модели и повторы выполнены до конца, без досрочного принятия, исключения моделей, увеличения выборки или изменения допусков по результатам этой серии. Протокол содержит хеши движка и проверочного скрипта и сохранён до запуска. Итог отрицательный: прошли `v1`, `v1a`, `v3`, `v4`; в остальных пяти моделях обнаружены непригодные повторы, включая блокировки и столкновения. Найденные случаи включены в регрессию ревизии 52. Эта серия проверяет именно ревизию 51 и не заменяет независимую проверку следующих изменений. Исходные отказы остаются частью истории проверки.

```sh
npm run test:convergence -- 1200 100 '' independent.json .2,.1,.05 50042
```

## Метрики и пригодность

Текущая очередь на дороге, внешняя очередь, ожидание активных участников и историческое ожидание завершивших этап разделены. Оконные ожидание и потеря времени используют интегралы внутри окна и учитывают незавершённые поездки. Средние не вычисляются только по успешно выехавшим участникам. Отдельно проверяются балансы участников и граница прогрева.

Ошибки модели/кода, столкновения, наезды, потеря автомобильного или пешеходного спроса, удаление участников после столкновения, ошибки маршрутов, устойчивые блокировки и диагностические вмешательства делают прогон непригодным. Непригодный результат сохраняется с причинами для расследования. Оптимизатор продолжает поиск после непригодного кандидата, но прекращает его при инфраструктурной ошибке. Применение возможно только после полной повторной проверки кандидата.

Парное сравнение требует одинаковых версий движка, шага, окна, прогрева, зёрен и входного спроса/маршрутов. Направление разности — вариант 2 минус вариант 1. Общий график использует те же условия допустимости. Отдельные диагностические графики непригодных повторов явно подписаны. Графики первых повторов не являются доверительными интервалами по всей выборке.

## Ресурсы и производительность

Интерактивный Worker получает один запрос за раз и выполняет ограниченные кванты. Ручная очередь ограничена восемью командами. После 30 с без ответа канал завершает Worker и сообщает ошибку; неудачный прогрев не запускает воспроизведение. Ответы старой модели после пересборки отбрасываются. Пул оптимизатора ограничен восемью Worker и 512 ожидающими заданиями.

Внешняя автомобильная очередь ограничена 1500 машинами на подход, пешеходы — 600 группами. Потерянный спрос учитывается и отклоняет прогон. При пешеходном переполнении часы прибытий продолжаются, свойства групп остаются воспроизводимыми после освобождения места; `ped-capacity.ts` проверяет это. Это отказ перегруженного расчёта, а не модель внешней пешеходной очереди.

Ряды прореживаются после 20 000 точек, история перемотки ограничена настройкой времени. Подробные ряды и журнал передаются примерно раз в секунду; во время восстановления времени — после достижения цели. PDF считает повторный прогон в Worker, но формирование векторного документа остаётся на главном потоке.

## Натурная проверка и внешние зависимости

Для каждого периода наблюдения нужны дата, длительность, геометрия, фазы и условия движения. В одинаковых интервалах измеряются потоки по направлениям и типам транспорта, очереди по полосам, интервалы выпуска, время проезда, стоянки автобусов и пешеходные потоки. Данные должны содержать единицы и оценку погрешности.

Измеренные значения, предположения и подобранные параметры разделяются. Независимый период резервируется для проверки после калибровки. Спрос, время реакции и интервалы следования проверяются анализом чувствительности. Наблюдения из разных условий не объединяются без обоснования. До такой проверки модель нельзя объявлять подтверждённым прогнозом реального перекрёстка.

Для проверки устройств нужны реальные целевые телефоны/планшеты и браузеры. Для исчерпывающей архивной совместимости нужны сохранения соответствующих исторических выпусков. Эти данные не заменяются синтетическими тестами.
