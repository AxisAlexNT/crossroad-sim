# Формат модели перекрёстка `crossroad-model`, версия 2

Модель — один JSON-объект. Единицы — метры и секунды. Начало координат — центр перекрёстка, ось x направлена на восток, ось y — на север.
Машинная схема формата — `schema/crossroad-model.schema.json`, типы TypeScript — `src/engine/types.ts`.

```json
{
  "format": "crossroad-model",
  "version": 2,
  "name": "Название",
  "description": "",
  "arms": [ ... ],
  "connections": [ ... ],
  "peds": { "nodes": [ ... ], "edges": [ ... ], "sources": [ ... ] },
  "signals": { "groups": [ ... ], "phases": [ ... ], "timing": { ... }, "offset": 0, "controller": "fixed", "code": "" },
  "spawners": { "<id подхода>": { ... } },
  "laneChoosers": { "<id подхода>": { ... } },
  "exits": { "<id подхода>": { ... } },
  "transit": { "enabled": true, "stops": [ ... ], "routes": [ ... ], "dwellMin": 60, "dwellMax": 90 },
  "sim": { ... },
  "basemap": null
}
```

## Подходы `arms`

Подход — дорога, примыкающая к перекрёстку. У каждого подхода есть полосы к перекрёстку `inLanes` и от него `outLanes`.
Полосы нумеруются от оси дороги к бордюру, начиная с нуля.

| Поле | Смысл |
|---|---|
| `id` | короткий идентификатор латиницей, на него ссылаются остальные разделы |
| `name`, `short` | полное и короткое название для подписей |
| `angle` | направление дороги от центра наружу, градусы: 0 — восток, 90 — север, 180 — запад, 270 — юг |
| `inLanes`, `outLanes`, `laneWidth` | число и ширина полос |
| `medianWidth`, `refuge` | ширина разделителя и есть ли на нём островок безопасности для пешеходов |
| `crosswalkOffset`, `crosswalkWidth`, `hasCrosswalk` | ось перехода от центра, ширина «зебры», есть ли переход |
| `stopLineGap` | зазор между переходом и стоп-линией |
| `approachLength`, `solidLength`, `exitLength` | длина подхода до стоп-линии, длина сплошной перед стоп-линией, длина выезда |
| `speedLimit` | разрешённая скорость, км/ч |
| `axisShift` | сдвиг оси дороги вправо, если смотреть от центра наружу |
| `color` | цвет машин с этого подхода |

Отношения «встречный подход» и «подход справа» вычисляются по углам, поэтому подходы могут идти под любыми углами.
Тип манёвра тоже определяется по углам: прямо, налево, направо или разворот.

## Разрешённые направления `connections`

Каждая связь соединяет полосу въезда с полосой выезда: `{ "id": "W0-N0", "from": { "arm": "W", "lane": 0 }, "to": { "arm": "N", "lane": 0 } }`.
Из полосы может быть несколько связей, например налево и прямо. Стрелки разметки на полосах рисуются по связям.
Поле `busOnly: true` разрешает направление только рейсовым автобусам: обычные машины его не выбирают, стрелка разметки для него не рисуется.

Манёвры, которые разметкой не разрешены, движок строит сам. Ими пользуются только рискованные водители, если в настройках задана вероятность такого нарушения.

## Пешеходы `peds`

Пешеходный граф описывает, где можно ходить.

- Узлы `nodes`: `corner` — угол между двумя соседними подходами `arms: [a, b]`, где b — следующий против часовой стрелки,
  `island` — островок безопасности на разделителе подхода `arms: [a]`, `point` — произвольная точка с координатами `x`, `y`.
  Положение углов и островков вычисляется по геометрии, `dx`, `dy` сдвигают его вручную.
- Рёбра `edges`: `{ "id": "NE~NW", "from": "NE", "to": "NW", "width": 4 }`. Если у концов ребра есть общий подход с переходом,
  ребро идёт по этому переходу через всю дорогу или до островка. Иначе ребро — прямая, например диагональный переход через перекрёсток.
- Источники `sources`: узел появления, число людей в час `rate`, скорость `speedMin` и `speedMax` в м/с,
  размеры групп `groups: [{ "size": 2, "share": 0.2 }]` и веса направлений `destinations`, где ключ — id узла.
  Маршрут выбирается по графу: кратчайший или близкий к нему по длине.

Пешеходы ждут разрешающего сигнала у бордюра и на островке. Начав переход, они его заканчивают. Если сигнал сменился, пока группа шла до островка, она ждёт на островке.

### Ряды и дополнительные траектории

- `arms[].twoRows: false` отключает два ряда на широкой полосе. По умолчанию полоса шириной от 4,2 м у перекрёстка работает как два ряда:
  налево встают слева, прямо и направо — справа, а на широком выезде потоки идут рядом и сливаются у перехода.
- `connections[].variants` — до четырёх дополнительных траекторий направления: `{ "shiftIn": -1.2, "bend": 0 }`.
  `shiftIn` — сдвиг на стоп-линии, плавно уходящий в ноль к выезду, `bend` — изгиб в середине, метры, плюс — влево по ходу.
  Сигнал направления действует на все его траектории, водитель сам выбирает свободную. Если `variants` заданы, ряды для этого направления не строятся.
  На полосе уже 4,2 м размах траектории ужимается с сохранением формы, чтобы машина оставалась в своей полосе. Траектории из одной полосы, которые снова сходятся или пересекаются, машины проезжают по очереди въезда.

## Светофоры `signals`

- `groups` — сигнальные группы. `kind`: `vehicle` — основной светофор, `arrow` — дополнительная секция со стрелкой, `pedestrian` — пешеходный светофор.
  `movements` — id связей для транспортных групп и id пешеходных рёбер для пешеходных. `arm` — у какого подхода рисовать светофор.
  У допсекции `parent` — id основного светофора, к которому она прикреплена, `side` — `left` или `right`, как видит водитель.
  `pedInfo: true` у основного светофора отмечает информационную секцию, которая предупреждает поворачивающих водителей о пешеходах.
  Она нужна для проверки по пункту 7.2.6 ГОСТ Р 52289-2019 и на движение в модели не влияет. Цвет `color` — только `#RRGGBB` или `#RGB`.
- `phases` — основные такты по порядку: `{ "id": "1", "name": "1: Тверская", "duration": 30, "green": ["N", "S"] }`. Длительность — целые секунды, включая мигание зелёного.
- `timing` — промтакт: жёлтый `yellow` 3 с, красный с жёлтым `redYellow` не более 2 с, мигание зелёного `flashGreen` 3 с, а также `allRed` и `pedClearance`.
- `offset` — сдвиг начала цикла. `controller`: `fixed` — фазы по кругу, `code` — функции `nextPhase()` и `phaseDuration()` из `code`.

Фаза, в которой горят только пешеходные группы, считается единой пешеходной фазой, сокращённо ЕПФ.

## Узлы с кодом `spawners`, `laneChoosers`, `exits`

Для каждого подхода: появление машин, выбор полосы в точке перестроения, выезд из модели.

- Узел без ручных правок записывается как `{ "id": "spawn-W", "params": { … }, "manual": false }`, без кода.
  Он работает встроенной логикой по параметрам, а код TypeScript для показа приложение пересоздаёт при загрузке.
- Узел с ручными правками записывается как `{ "id": "spawn-W", "params": { … }, "code": "…", "manual": true }`.
  Его код выполняется в изолированной песочнице: в отдельном интерпретаторе JavaScript без доступа к странице, сети, файлам и хранилищу браузера,
  с ограничением времени вызова и памяти. Если код ошибается много раз подряд, узел переходит на параметры.
- Контроллер светофора: поле `signals.code` записывается только при `controller: "code"`.
- Появление машин `arrival`: `poisson` — пуассоновский поток, накопленная интенсивность до следующей машины распределена показательно,
  поэтому моменты появления не зависят от шага расчёта, а ступенчатый профиль `profile` учитывается точно.
  `uniform` — равные интервалы, `platoon` — пачки по `platoonSize` машин.

Пределы загружаемого файла: не больше 12 МБ, 8 подходов, 6 полос в каждую сторону, 400 связей полос, 80 сигнальных групп, 32 фаз,
200 пешеходных узлов, 400 переходов, 40 остановок, 80 маршрутов, 100 000 символов кода на узел. Строки обрезаются до 200 символов,
описание — до 4000, числа приводятся к допустимым диапазонам, цвета принимаются только в виде `#RRGGBB` или `#RGB`.

При загрузке файла, где есть узлы с ручными правками или контроллер в режиме кода, приложение показывает список таких узлов
и предлагает загрузить модель с кодом, без кода или отменить загрузку. Контракты функций — в README и `src/engine/types.ts`.

## Автобусы `transit`

- `stops` — остановки: `{ "id": "OB-W", "name": "…", "arm": "W", "side": "exit", "dist": 20, "bay": true }`.
  `side`: `approach` — на полосах к перекрёстку, `exit` — на полосах от него. `dist` — расстояние от стоп-линии или от начала выезда, м.
  `bay` — заездной карман: на время стоянки автобус освобождает полосу.
- `routes` — маршруты: `{ "id": "330-NW", "name": "330 к улице Анисимова", "from": "N", "to": "W", "stops": ["TV-in", "OB-W"], "perHour": 6.7, "length": 12, "headway": "6–12 мин", "enabled": true }`.
  `perHour` — автобусов в час в этом направлении, `headway` — интервал по расписанию для справки.
- `dwellMin`, `dwellMax` — время стоянки на остановке, с. Значение выбирается случайно в этом диапазоне.

Крупные машины без маршрута задаются долей типа `bus` в узлах появления машин.

## Параметры симуляции `sim`

| Поле | Смысл |
|---|---|
| `dt`, `seed` | шаг расчёта и зерно генератора случайных чисел |
| `riskyShare` | доля рискованных водителей |
| `violations` | вероятности нарушений для рискованного водителя: `solidLine`, `stopLine`, `redLight`, `illegalTurn` |
| `obstructedVisibility`, `normalVisibility` | видимость встречного потока, м |
| `criticalGapLeft`, `criticalGapOther` | критические интервалы для уступающих манёвров, с |
| `petDanger`, `petWindow`, `ttcDanger` | пороги опасных моментов, с |
| `crashPersist`, `crashDuration` | столкнувшиеся машины перекрывают проезд, время до освобождения, по умолчанию 1200 с |
| `pathSpread` | неявные траектории: водитель едет по своей кривой около основной, со сдвигом у стоп-линии и изгибом в середине. По умолчанию включено |
| `implicitShift`, `implicitBend` | границы сдвига и изгиба неявной траектории, м, по умолчанию 1. Вместе они не выходят за запас полосы |
| `trajectoryChoice` | как водитель выбирает из дополнительных траекторий: `random` — любую доступную случайно, по умолчанию, `free` — ту, где впереди свободнее |
| `drivers` | водители: ускорение легковых `accelMin`–`accelMax` 2,4–3 м/с², грузовых `heavyAccel` 1,35 м/с², желаемая скорость `speedMin`–`speedMax` 0,9–1,1 от разрешённой, интервал `headwayMin`–`headwayMax` 1–1,4 с, расстояние `gap` 1,5 м, у рискованных интервал и расстояние ×`riskyFactor` 0,7, время реакции при трогании `reactionMin`–`reactionMax` 0,3–0,8 с. В точке появления `params.drivers` задаёт для каждого параметра свой диапазон `min`, `max` и распределение `dist`: `uniform`, `normal` или `triangular` |
| `missedTurn`, `lcPatience` | что делает водитель, не успевший перестроиться: `reroute` — сразу едет по направлению, разрешённому из своей полосы, `wait` — ждёт окна не дольше `lcPatience` секунд |
| `deadlockSeconds`, `deadlockBreak` | через сколько секунд взаимного ожидания фиксируется блокировка и через сколько водители выходят из неё, 0 — никогда |
| `slowdownWindow`, `slowdownRatio` | окно и порог предупреждения о падении средней скорости |
| `noProgressSeconds` | предупреждение, если при разрешающем сигнале столько секунд нет проезда |
| `historySeconds` | длина истории для перемотки |

## Подложка `basemap`

Необязательная векторная подложка. Её можно загрузить в настройках из выгрузки OpenStreetMap в формате `.osm` или GeoJSON.
Показ подложки по умолчанию выключен.

- `builtin` — имя встроенной в приложение подложки, например `"kolpino"`. Тогда `features` пустой, объекты берутся из приложения,
  а в файле хранятся только привязка и поворот. Модель Колпино по умолчанию ссылается на встроенную подложку.

- `origin` — широта и долгота точки, которая совмещается с центром перекрёстка.
- `rotation`, `dx`, `dy` — поворот в градусах против часовой стрелки и сдвиг в метрах для точного совмещения.
- `features` — объекты `{ "k": "building", "g": [x0, y0, x1, y1, …], "closed": true, "name": "…", "hw": "residential" }`.
  `k`: `building`, `road`, `path`, `water`, `green`, `rail`, `parking`, `area`. Координаты в метрах относительно `origin`.
- `attribution` — строка об авторстве данных. Для OpenStreetMap: «© участники OpenStreetMap, лицензия ODbL». Она показывается на карте и в экспорте.

## Первая версия формата

Файлы версии 1, где подходы заданы объектом с ключами N, E, S, W без углов и пешеходного графа, открываются автоматически:
углы ставятся по сторонам света, пешеходный граф строится по переходам, общий поток пешеходов распределяется по углам.
